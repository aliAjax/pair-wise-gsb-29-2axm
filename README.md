# 出车核验台 · 末端配送

站点分单完成后、车辆出门前的逐件核验台：扫件与分单清单逐件比对，
缺件、多件、温区不符一律回待处理区；确认无误才能封车，封车后改动必须
登记解封原因和复核人。

- 行业：物流（末端配送）
- 技术栈：Vue 3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则自测：`npm run test:rules`

## 作业流程

1. **新建波次**：选择骑手、本车温区（常温/冷藏/冷冻）、计划封车时刻，
   勾选同温区的已分单包裹，生成核验波次。
2. **逐件扫件**：扫一件对一件——
   - 对上：清单内且温区一致，记为已扫；
   - 缺件：清单有、本轮没扫到，封车被拦截；
   - 多件：不在本波次清单（或查无资料），回待处理区；
   - 温区不符：如冻品扫进常温车，立即拦截；
   - 重复扫件给出提示，不重复计数。
3. **退回待处理区**：原分配清单与全部已扫记录保留，仅开启新一轮核验。
4. **封车**：缺件/多件/温区不符全部清零才允许封车，记录封车人与时刻。
5. **解封**：封车后要改，只能登记解封原因与复核人，随后进入新一轮核验；
   历次封车/解封记录都可在留档中追溯。

## 代码分层

| 目录 | 职责 |
| --- | --- |
| `src/domain/types.ts` | 包裹、温区、波次、扫件事件、封解封等领域模型 |
| `src/domain/rules.ts` | 核验规则（纯函数）：扫件判定、缺/多/温区比对、封车校验 |
| `src/domain/seed.ts` | 演示用包裹资料与波次种子数据 |
| `src/data/archive.ts` | 本地留档：包裹资料 / 波次 / 操作日志分 key 存 localStorage |
| `src/stores/dispatch.ts` | Pinia 状态：建波、扫件、退回、封车、解封、日志 |
| `src/components/` | 操作页面：波次列表、核验台、包裹资料库、留档台账 |
| `scripts/check-rules.mts` | 核验规则口径的断言自测 |

## 留档与重开

- 数据保存在站点浏览器 localStorage，三个 key 分开：包裹资料、波次核验
  （含清单快照、全部扫件流水、封解封记录）、只追加的操作日志。
- 重开页面后可按**骑手**和**波次号**筛选核对；“本地留档”页可导出整份
  JSON 用于交接留底。
- 操作人填写后随每条日志署名（封车人、解封复核人均必填）。
